# 系统交互边界

输入、显示、传感器、权限和 AppOps 都属于系统交互能力。它们经常能直接影响用户正在操作的设备，因此文档中按“读取、临时控制、长期修改”分层理解。

## 能力分层

| 层级 | 说明 | 示例 |
| --- | --- | --- |
| 读取状态 | 只查询当前系统状态 | 屏幕尺寸、刷新率列表、输入法区域、传感器读数 |
| 临时控制 | 改变当前交互状态，可快速恢复 | 显示/隐藏输入法、临时显示刷新率、触摸禁用后恢复 |
| 长期修改 | 改变系统或应用长期状态 | AppOps 模式、组件状态、传感器隐私、显示模式 |

读取状态可以作为普通高级教程。临时控制必须说明恢复方式。长期修改必须说明作用对象、风险和回滚路径。

## Input

Input 服务可以查询输入设备、注入输入事件、管理触摸和键盘相关状态。通过 `input` 服务禁用/恢复触摸设备属于高风险临时控制，必须准备恢复入口。

注意：

- 输入事件可能作用到错误应用。
- 禁用触摸可能让设备难以恢复。
- 输入注入比普通自动输入风险更高。
- 直接调用 `IInputManager` 需要确认参数和当前设备状态。

## Display

Display 服务和 SurfaceFlinger 相关能力常用于显示信息、刷新率、亮度、窗口模式等。

注意：

- 读取支持的刷新率相对安全。
- 切换刷新率显示开关属于临时控制。
- 设置显示模式、窗口模式、显示电源属于高风险。
- 多显示屏和横竖屏会影响坐标、截图、OCR、悬浮窗。

## Sensor

传感器能力分两类：

- 普通传感器数据：光线、加速度、方向、距离、磁场。
- 传感器隐私开关：摄像头、麦克风、全局 Sensors off。

普通传感器读取需要注册监听器并及时注销。传感器隐私写入会改变用户隐私状态，必须提供恢复路径。

## AppOps / Permission

AppOps 用于检查、记录和控制应用操作状态。它不是普通运行时权限的简单替代。

适合教程化说明：

- 如何判断能力是否与权限/AppOps 有关。
- 如何从服务资料理解风险。
- 何时不应该直接调用 `setMode(...)`。

不适合直接给复制示例：

- 批量修改 AppOps。
- 无确认重置权限状态。
- 监听或操作带 callback 的 AppOps 接口。

## 设计原则

```text
先读取状态
  -> 输出给用户确认
  -> 只在必要时执行写操作
  -> 写入后验证结果
  -> 提供恢复动作
```

系统交互脚本不要默认放进高频自动触发器。先做成一键指令，验证稳定后再接规则。

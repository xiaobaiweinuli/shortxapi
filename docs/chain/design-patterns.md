# 动作链设计模式

这页把常见规则拆成可复用结构。写复杂规则时，先选模式，再写具体动作。

## 过滤后处理

适合通知、应用前台、剪贴板变化。

```text
触发器
  -> 条件过滤包名/文本/状态
  -> ExecuteJS 提取值
  -> MatchJS 判断是否有效
  -> 执行动作
```

特点：

- 条件层只做粗过滤。
- JS 负责提取和清洗。
- MatchJS 只判断结果是否继续。

## 交互选择

适合从列表中选择应用、设置项、组件、命令。

```text
ExecuteJS 生成 JSON 列表
  -> ShowListDialog
  -> selectedListItem
  -> ExecuteJS 解析 __value
  -> 后续动作
```

适合使用 `name`、`summary`、`__value`、`__icon`。

## 快照比较

适合设置项监视器、配置变化、包列表变化。

```text
读取当前状态
  -> 与全局变量旧快照比较
  -> 生成差异 JSON
  -> 展示差异
  -> 更新快照
```

注意：

- 旧快照要存全局变量或文件。
- 差异项用 JSON 表达，不要只拼接展示文本。
- 恢复命令应由用户确认后执行。

## 去重锁

适合验证码、通知、重复触发控制。

```text
提取业务 key
  -> 读取全局变量 lastKey
  -> 相同则停止
  -> 不同则执行
  -> 写入新 key
```

去重值应保持小而明确，例如 hash、时间戳、消息 ID，不要无限追加原始通知内容。

## 诊断面板

适合日志、任务状态、插件能力、配置清单。

```text
读取状态
  -> 生成菜单 JSON
  -> ShowListDialog
  -> 根据 selectedListItem 执行诊断动作
```

诊断动作建议是手动一键指令，不要放进自动规则高频触发。

## 高风险确认

适合删除配置、清空日志、修改系统设置、执行 Shell。

```text
生成待执行摘要
  -> ShowAlertDialog 或选择确认
  -> 用户确认
  -> 执行高风险动作
  -> 输出结果和恢复提示
```

不要把高风险动作直接接在触发器后面。

## 外部能力加载

适合 QR、邮件、拼音、第三方 jar/dex。

```text
确认 lib 文件存在
  -> PathClassLoader 加载
  -> 反射或直接调用
  -> 输出稳定结果
```

外部库脚本应标注依赖文件路径和版本，不要只给一段无法独立判断环境的代码。

# 风险分级

ShortX 高级能力可以触达 Android 系统服务和 ShortX 内部服务。文档中的能力都应按风险分级理解：能读取不等于能写入，能调用不等于适合放进自动规则。

## 分级总览

| 级别 | 含义 | 是否适合复制示例 |
| --- | --- | --- |
| 普通 | 主要影响当前动作链或用户可恢复的临时状态 | 可以给完整示例 |
| 高级 | 可能改变长期状态，或依赖 Android/ShortX 运行边界 | 给前提、确认、恢复 |
| 危险 | 可能导致数据删除、系统异常、设备不可用或安全状态变化 | 不给无确认的一键脚本 |

## 普通能力

普通能力主要影响当前动作链或用户可恢复的临时状态。

示例：

- Toast、弹窗、列表对话框。
- 剪贴板读写。
- 普通字符串处理。
- JSON 列表生成。
- 读取全局变量。
- 读取包名、标题、通知正文等上下文。

教程写法：

```text
输入是什么
  -> 脚本如何处理
  -> 输出到哪个上下文名
  -> 下游怎么读取
```

普通能力也要避免声明上下文保留名，例如不要写 `var pkgName`、`var selectedListItem`、`var jsRet`。

## 高级能力

高级能力可能改变长期状态，或依赖 Android/ShortX 运行边界。

示例：

- 写全局变量。
- 修改系统设置。
- 查询或切换组件状态。
- 创建悬浮窗。
- 调用内部 ShortX 服务读取配置。
- 读取传感器、网络、通知、显示状态。
- 加载外部 dex/jar。

处理原则：

- 先做只读验证。
- 输出 JSON 诊断结果，避免静默失败。
- 写入前展示当前值和目标值。
- 写入后提供恢复动作或恢复说明。
- 不放进高频自动触发器，除非有严格过滤和去重。

## 危险能力

危险能力可能导致系统重启、服务崩溃、数据删除、设备不可用或安全状态变化。

示例：

- `reboot(...)`
- `crashSystemServer()`
- 删除规则、直接动作、代码库、全局变量或 ShortX 配置。
- 修改锁屏凭据、ADB 授权、传感器隐私、应用隐藏、组件禁用。
- 直接写 Android 系统服务关键状态。

处理原则：

- 不作为入门示例。
- 不包装成“复制即用”的无提示代码。
- 必须明确作用对象、恢复路径和失败后果。
- 优先写查阅方法、调用边界和风险说明。

## 自动规则额外风险

同一个动作放在一键指令里和自动规则里，风险不一样。

| 场景 | 风险变化 |
| --- | --- |
| 手动一键指令 | 用户主动触发，可观察、可取消 |
| 通知自动规则 | 可能被重复通知触发 |
| 应用前台触发 | 可能高频反复执行 |
| Method Hook | 依赖目标方法签名，错误影响更大 |
| 定时触发 | 失败可能长期重复 |

自动规则里使用写入类能力时，至少要有：

- 来源过滤。
- 去重状态。
- 超时或取消分支。
- 日志或提示。
- 恢复方式。

## 文档自检

写教程时检查：

- 这段能力是读取、写入还是删除？
- 影响只在当前链路，还是会持久化？
- 是否会影响其他 App、其他用户或工作资料？
- 是否有失败时的可观察输出？
- 用户能不能恢复？
- 是否把危险能力伪装成普通按钮？

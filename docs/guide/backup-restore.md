# 备份与恢复

ShortX 高级规则常常会修改全局变量、代码库、动态快捷方式、系统设置和内部配置。只导出一键指令或自动指令本身，不等于完整备份。

## 需要备份什么

| 数据 | 为什么需要备份 |
| --- | --- |
| 一键指令集 | 手动入口和复合动作链 |
| 自动指令集 | 触发器、条件、动作和上下文映射 |
| 代码库片段 | 多条规则可能共享 |
| 全局变量 | 配置、状态、缓存、去重标记 |
| 开关指令 | 运行开关和状态控制 |
| 动态快捷方式配置 | 桌面入口和 Intent URI |
| 系统设置快照 | 修改 Settings 前后的恢复依据 |

如果规则依赖外部插件，还要记录插件包名、版本和提供的动作/条件。

## 备份前清理

备份前先确认：

- 调试日志是否需要保留。
- 全局变量中是否包含 secret。
- 剪贴板历史是否不该导出。
- 旧的临时变量和缓存是否可以删除。
- 是否有运行中任务正在修改同一批数据。

不要把日志、剪贴板、通知正文、令牌等敏感内容当作普通配置一起打包。

## 推荐流程

```text
读取配置数据
  -> 生成清单
  -> 标记敏感项
  -> 导出前确认
  -> 保存备份
  -> 在新设备上按依赖顺序恢复
  -> 禁用状态下测试
```

恢复顺序参考 [发布与迁移](/guide/release-migration)。

## 全局变量恢复

全局变量不是单一字符串，它可能有类型、备注、secret 标记和创建来源。恢复时要确认：

- 变量名没有和新设备已有规则冲突。
- secret 值是否允许导出。
- 列表型变量是否仍符合新规则预期。
- 去重类变量是否应该清空，而不是带到新设备。

例如验证码去重 hash 通常不需要迁移；用户配置项才需要迁移。

## 系统设置恢复

修改 Settings、权限、AppOps、显示、输入、通知策略前，应先做快照。

建议链路：

```text
读取原始状态
  -> 写入全局变量或备份文件
  -> 执行修改
  -> 验证结果
  -> 提供恢复动作
```

不要只提供“设置动作”，不提供“恢复动作”。

## 恢复验证

恢复后按这个顺序测试：

1. 代码库片段是否存在。
2. 全局变量是否能读取。
3. 插件能力是否可发现。
4. 一键指令能否手动运行。
5. 自动规则触发器是否正确。
6. 高风险动作是否仍处于禁用或确认状态。

不要在恢复后立即启用所有自动规则。

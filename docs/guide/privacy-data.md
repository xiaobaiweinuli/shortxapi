# 隐私数据处理

ShortX 高级规则经常处理通知、剪贴板、日志、数据库、截图、OCR、HTTP 请求和系统状态。只要数据离开当前动作链，风险就会明显升高。

## 敏感来源

| 来源 | 可能包含 |
| --- | --- |
| 通知 | 标题、正文、验证码、支付信息、聊天摘要 |
| 剪贴板 | 密码、验证码、令牌、地址、账号 |
| 日志 | URL、请求体、异常堆栈、脚本输出 |
| 全局变量 | secret、配置、缓存状态 |
| 数据库 | 联系人、消息、业务数据 |
| 截图/OCR | 屏幕上所有可见内容 |
| 网络请求 | token、Cookie、表单、远端返回 |

默认策略：不上传、不长期保存、不完整记录。

## 最小化原则

只保留完成任务必需的字段：

```javascript
var output = {
    ok: true,
    source: "notification",
    matched: true
};

JSON.stringify(output);
```

不要把整条通知、完整剪贴板或完整日志塞进全局变量。需要排查时，先输出摘要，再由用户手动复制详细内容。

## 脱敏建议

```javascript
function maskText(textValue) {
    var sourceText = textValue == null ? "" : String(textValue);
    if (sourceText.length <= 6) {
        return "***";
    }
    return sourceText.substring(0, 3) + "***" + sourceText.substring(sourceText.length - 3);
}

maskText("abcdef123456");
```

对 token、手机号、邮箱、Cookie、URL query、数据库记录都应做类似处理。

## 网络上传

上传前必须确认：

- 目标 URL 是否固定可信。
- 上传字段是否最小化。
- 是否包含通知正文、剪贴板、截图路径、数据库结果。
- 失败重试是否会重复上传。
- HTTP 日志是否会保存请求体。

自动规则不要默认上传隐私数据。需要远端通知时，优先上传摘要。

## 文件与数据库

读写 ShortX 目录或目标应用数据库时：

- 明确文件路径和用途。
- 临时文件放在固定子目录。
- 输出报告前过滤敏感字段。
- 提供清理动作。
- 不把数据库原文件作为普通附件发送。
- 外部 dex/jar 来源和版本要写清楚。

## 发布说明

发布含隐私数据处理的规则时，说明：

| 项目 | 要写清 |
| --- | --- |
| 读取 | 读取哪些来源 |
| 保存 | 保存到全局变量、文件还是日志 |
| 上传 | 是否发 HTTP、邮件或 WebDAV |
| 展示 | 是否弹窗、通知或复制剪贴板 |
| 清理 | 如何删除缓存和报告 |
| 失败 | 失败时是否保留中间数据 |

用户导入前应该知道规则会碰哪些数据。

# 安全边界

ShortX 高级能力可以触达系统服务、内部配置、文件、剪贴板、通知和网络。文档中的示例默认面向理解和受控使用，不鼓励把高风险能力包装成无提示的一键操作。

## 敏感数据

常见敏感来源：

- 通知标题和正文。
- 短信、验证码、支付提醒。
- 剪贴板当前内容和历史内容。
- HTTP 请求体、URL、Cookie、token。
- JS/HTTP/Hook 日志。
- 全局变量中的 secret。
- 包名、组件名、位置、Wi-Fi、蓝牙、设备信息。

处理这些数据时，默认不要上传、不要持久化、不要在日志里完整输出。

## 网络边界

HTTP 动作和脚本请求前应确认：

- 上传了哪些字段。
- 目标 URL 是否固定且可信。
- 是否包含通知、剪贴板、位置、账号信息。
- 是否开启了 HTTP 请求日志。
- 失败时是否会重试并重复上传。

调试阶段可以记录摘要，不要记录完整敏感 payload。

## 系统状态边界

修改这些状态前要有恢复路径：

- Settings Provider。
- 通知策略、DND、渠道。
- 输入、显示、刷新率、触摸。
- 权限、AppOps、组件启用状态。
- 动态快捷方式。
- ShortX 规则、代码库、全局变量。

危险能力应放在手动确认链路中，不放在高频自动触发器后面。

## 内部服务边界

`OooO0O0.OooO00o()` 是高级规则中常用的内部服务入口。它很有用，但也意味着更依赖 ShortX 内部实现。

使用原则：

- 只在当前版本做过最小验证的能力上使用。
- 不凭方法名猜 `ByteArrayWrapper` 参数。
- 删除、清空、写入配置前二次确认。
- 文档中标注“内部服务能力”，不要伪装成稳定公共 API。

## 自动触发边界

自动规则比一键指令风险更高，因为它会在后台触发。

自动规则中应避免：

- 无确认删除配置。
- 无确认执行 Shell。
- 无确认上传剪贴板或通知。
- 高频读取大日志或内部文件。
- 失败后无限重试。
- 修改系统状态后没有回滚。

复杂规则建议先做成一键指令，手动验证稳定后再接自动触发器。

## 发布边界

分享规则时应说明：

- 会读取哪些上下文变量。
- 会写哪些全局变量。
- 会修改哪些系统或 ShortX 配置。
- 是否依赖插件、系统版本或 ROM。
- 是否包含网络请求。
- 如何禁用和恢复。

不要把高风险前提藏在代码里。
